Dokumentasi Kode Sonora-Flutter

Panduan lengkap struktur arsitektur, cara kerja logika baris demi baris, dan komponen UI aplikasi pemutar musik Sonora. Didesain ramah untuk pengembang tingkat pemula (junior developer).

Flutter 3.44+ Dart 3.12+ Android Native Media3

1. Gambaran Umum Proyek

Sonora-flutter adalah aplikasi klien musik pribadi berbasis YouTube Music dengan pendekatan Standalone-First. Aplikasi dapat memutar musik secara langsung dari YouTube tanpa server eksternal, sekaligus menyediakan dukungan opsional untuk Proxy Sonora (Node.js).

Aplikasi ini memiliki prinsip Pemisahan Tugas Bersih (Clean Separation of Concerns):

  • Playback Mandiri (Standalone Direct): Menggunakan youtube_explode_dart untuk ekstraksi metadata dan resolusi stream audio langsung dari CDN GoogleVideo tanpa konfigurasi server.
  • Proxy Sonora (Backend Node.js Opsional): Mendukung koneksi ke instance proxy self-hosted untuk endpoint /home, /search, dan /browse terpusat.
  • Sonora Flutter (Client Android): Menampilkan antarmuka Nocturne Audio dengan aksen Crimson, mengelola antrean lagu, mendukung lirik sinkron via LRCLIB, dan memutar audio native di latar belakang via Android Media Session.

2. Arsitektur & Jalur Audio

[Flutter UI] ---> [SonoraAudioHandler (just_audio)] ---> [LockCachingAudioSource]
     │                                                               │ (Audio M4A / Opus)
     │ (Resolusi Direct / Fallback Proxy)                            ▼
     ├──> [YouTubeMusicService] ==========================> [CDN GoogleVideo]
     │                                                               │ (Range Request 206)
     └──> [SonoraApi (Opsional)] ---> [Sonora Node Proxy]             │
💡 Bagaimana client memutar audio tanpa server proxy?

Aplikasi mengurai StreamManifest menggunakan youtube_explode_dart langsung di perangkat dan memprioritaskan stream audio berkualitas tinggi. Pemutar audio menggunakan mekanisme caching lokal (LockCachingAudioSource) untuk pre-buffering sehingga audio diputar mulus tanpa gangguan latensi jaringan.

File ini adalah fondasi awal saat aplikasi dibuka. Bertugas melakukan bootstrapping asinkron sebelum widget utama ditampilkan.

Baris Penting & Penjelasannya:

// 3. Jika audio berhasil siap:

// Menampilkan layar fallback ramah pengguna dengan tombol "Coba lagi", BUKAN crash putih!

4. Data Layer: lib/data/music_models.dart

Menyimpan representasi objek data musik yang diterima dari proxy. Menggunakan pola Parsing Toleran: jika YouTube mengubah format JSON atau ada field bernilai null, aplikasi tidak akan crash.

Class / Properti Tipe Fungsi & Logika
MusicItem Class (Immutable) Merepresentasikan satu lagu, video, album, playlist, atau artis.
isPlayable Getter bool Mengembalikan true HANYA jika videoId ada dan tidak kosong. Digunakan untuk menyaring item mana yang bisa diklik play.
artist Getter String Hierarki fallback cerdas: Jika daftar artists[] ada, digabung dengan koma (mis. "Artist A, Artist B"). Jika kosong, menggunakan teks subtitle. Jika tetap kosong, mengembalikan string kosong "".
browseTarget Getter String? Menentukan ID untuk membuka detail. Jika ada browseId (album/artis), dipakai langsung. Jika adanya playlistId, otomatis dinormalkan dengan awalan kanonik VL.
MusicSection Class Mewakili satu rak/koleksi (misalnya rak "Quick picks" atau "Trending") yang berisi title dan List<MusicItem> items.

5. Data Layer: lib/data/settings_store.dart

Mengelola pengaturan URL proxy lokal menggunakan SharedPreferences. Mengikuti aturan keamanan ketat: tidak ada password/cookie rahasia yang disimpan.

Alur Logika & Aturan Validasi:

  • Persist-First: Data ditulis ke disk terlebih dahulu (prefs.setString). Jika disk gagal/penuh, exception dilempar, state memori TIDAK diubah, dan UI tidak dibohongi dengan status "sukses palsu".
  • Sanitasi URL (normalizeProxyBase):
    • Hanya menerima skema http:// atau https://.
    • Menolak kredensial di URL (misal http://user:pass@host).
    • Menolak query string (?foo=bar) atau fragment (#section).
    • Menghapus garis miring berlebih di akhir (misal http://host/// → http://host).
    • Mempertahankan subpath (misal http://host/sub/api tetap utuh).
  • Pembersihan Bersih: Mengosongkan URL akan menyimpan string kosong "", bukan menghapus key. Ini mencegah nilai bawaan build (--dart-define) muncul kembali secara tidak diinginkan setelah pengguna sengaja mengosongkannya.
  • Persistensi Draf (sonora.proxyDraft): Ketika toggle Add-on dimatikan, proxyBase dikosongkan agar aplikasi beroperasi dalam mode mandiri, namun alamat URL tetap tersimpan sebagai draf dan otomatis terisi kembali saat toggle diaktifkan.

6. Data Layer: lib/data/sonora_api.dart

Klien HTTP yang mengirimkan permintaan ke proxy Sonora.

Fungsi-Fungsi Utama:

// 1. Mengambil feed beranda (Quick picks, dsb)
Future<List<MusicSection>> home();

// 2. Pencarian dengan filter kategori opsional (song, video, album, playlist)
Future<List<MusicSection>> search(String query, {String? filter});

// 3. Mengambil daftar lagu dari album atau playlist
Future<List<MusicSection>> browse(String id);

// 4. Uji koneksi: Memastikan HTTP 200 DAN JSON memuat {"ok": true}
Future<void> checkConnection(String base);

// 5. Membuat URI stream relay ke proxy
Uri streamUri(String videoId);
🔒 Mengapa ada fungsi _captureBase()?

Ketika pengguna menekan tombol Search, URL proxy aktif langsung ditangkap saat request dimulai. Jika pengguna membuka Pengaturan dan mengganti URL proxy saat pencarian masih berjalan di latar belakang, hasil pencarian lama tidak akan merusak request baru karena base URL sudah terkunci sejak awal.

6b. Data Layer: lib/data/youtube_music_service.dart

Layanan ekstraksi YouTube langsung di sisi klien menggunakan pustaka youtube_explode_dart. Memungkinkan pemutaran dan pencarian mandiri tanpa ketergantungan pada server proxy.

Fungsi-Fungsi Utama:

// 1. Mengambil direct stream URI dengan bitrate audio tertinggi (M4A / Opus)
Future<Uri?> resolveStreamUri(String videoId);

// 2. Pencarian lagu langsung dari YouTube
Future<List<MusicItem>> search(String query);

// 3. Mengambil daftar lagu trending langsung dari feed YouTube
Future<List<MusicItem>> getTrending();

// 4. Mengambil koleksi lagu playlist YouTube hingga 50 trek atau fallback pencarian
Future<List<MusicSection>> browse(String browseId, {String? title, String? type, int limit = 50});
  • Stream Resolution Bebas 403: Memprioritaskan stream audio berkualitas tinggi yang dapat diakses langsung oleh Android ExoPlayer dengan respon 206 Partial Content.
  • Memory Caching (4 Jam): Menyimpan cache URI stream selama 4 jam untuk menghindari overhead panggilan manifest berulang ke YouTube.
  • Dukungan Browse Mandiri: Membaca trek playlist YouTube secara langsung via _yt.playlists.getVideos() atau fallback cerdas via search() tanpa dependensi proxy.
  • Dispose Safety: Mengimplementasikan dispose() aman untuk membebaskan koneksi HTTP client YoutubeExplode.

6c. Data Layer: lib/data/lyrics_store.dart

Penyedia lirik tersinkronisasi (*synced lyrics*) yang mengambil data langsung dari LRCLIB tanpa melalui server proxy.

Kemampuan & Pola Ketahanan:

  • fetchLyrics({required String title, required String artist, int? durationSeconds}): Mencari lirik sinkron berdasarkan judul dan artis lagu.
  • LyricsRepository.parseSynced(String lrc): Mengurai string format LRC menjadi daftar pasangan waktu (*timestamp*) dan baris lirik.
  • Graceful Degradation: Kegagalan jaringan atau ketiadaan lirik selalu mengembalikan null secara aman dan tidak pernah melempar pengecualian (*never throws*).

6d. Data Layer: lib/data/audio_cache_service.dart

Layanan pengelolaan cache berkas stream audio pada penyimpanan lokal perangkat (direktori temporary sistem).

Fungsi-Fungsi Utama:

// 1. Menghitung ukuran total berkas cache audio di disk
Future<int> getCacheSizeBytes();

// 2. Membersihkan seluruh berkas cache audio secara manual
Future<void> clearCache();

// 3. Pemangkasan otomatis LRU (batas 500 MB, dipangkas ke 400 MB)
Future<void> pruneCache({int maxBytes, int targetBytes});

// 4. Formatter ukuran byte ke string terbaca (B, KB, MB, GB)
String formatBytes(int bytes);
  • Pembersihan Otomatis LRU: Dijalankan saat startup aplikasi dan setelah antrean lagu dimuat. Bila ukuran cache melebihi 500 MB, sistem memangkas berkas yang paling lama tidak diakses (*Least Recently Used*) hingga tersisa 400 MB.
  • Pembersihan Manual: Tersedia tombol pembersih di layar Pengaturan disertai visualisasi progress bar penggunaan memori real-time.

7. Local Storage: lib/data/local_database.dart (7 Tabel SQLite)

Menggunakan SQLite native via paket sqflite untuk menyimpan data offline lokal di perangkat pengguna. Terdiri dari 7 tabel fisik yang mencakup 5 domain modul:

Tabel 1: playback_history (Riwayat Lagu yang Diputar)

Mencatat setiap lagu yang pernah diputar di aplikasi untuk fitur "Recently Played".

CREATE TABLE playback_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  video_id TEXT NOT NULL,
  title TEXT NOT NULL,
  artist TEXT NOT NULL,
  thumbnail TEXT,
  duration TEXT,
  played_at INTEGER NOT NULL -- timestamp Unix epoch (ms)
);
CREATE INDEX idx_playback_history_played_at ON playback_history(played_at DESC);
CREATE INDEX idx_playback_history_video_id ON playback_history(video_id);
  • recordPlayback(MusicItem item): Menambahkan riwayat putar dengan batas maksimal 100 entri terbaru (*auto-capping*).
  • getRecentPlaybacks({int limit = 20}): Mengambil daftar lagu terakhir diputar.
  • clearPlaybackHistory(): Mengosongkan seluruh riwayat pemutaran.

Tabel 2: favorite_tracks (Daftar Lagu Favorit Lokal)

Menyimpan lagu-lagu yang ditandai favorit (disukai) secara offline.

CREATE TABLE favorite_tracks (
  video_id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  artist TEXT NOT NULL,
  thumbnail TEXT,
  duration TEXT,
  added_at INTEGER NOT NULL
);
CREATE INDEX idx_favorite_tracks_added_at ON favorite_tracks(added_at DESC);
  • addFavorite(MusicItem item): Menyimpan lagu favorit (ConflictAlgorithm.replace).
  • removeFavorite(String videoId): Menghapus lagu dari favorit.
  • isFavorite(String videoId): Mengecek status favorit lagu.
  • getFavorites({int limit = 50}): Mengambil daftar lagu favorit.

Tabel 3: search_history (Riwayat Pencarian & Frekuensi)

Menyimpan kata kunci pencarian yang pernah diketik pengguna beserta frekuensinya.

CREATE TABLE search_history (
  query TEXT PRIMARY KEY,
  filter TEXT,
  searched_at INTEGER NOT NULL,
  search_count INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_search_history_searched_at ON search_history(searched_at DESC);
  • recordSearch(String query, {String? filter}): Menyimpan pencarian dengan auto-capping 30 entri.
  • getRecentSearches({int limit = 10}): Mengambil kata kunci pencarian terbaru.
  • deleteSearch(String query) & clearSearchHistory(): Menghapus riwayat pencarian.

Tabel 4 & 5: user_playlists & playlist_tracks (Playlist Lokal)

Menyimpan playlist kustom buatan pengguna beserta relasi lagu di dalamnya.

CREATE TABLE user_playlists (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT NOT NULL DEFAULT '',
  artwork_url TEXT,
  artwork_path TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE playlist_tracks (
  playlist_id TEXT NOT NULL,
  video_id TEXT NOT NULL,
  title TEXT NOT NULL,
  artist TEXT NOT NULL DEFAULT '',
  thumbnail TEXT,
  duration TEXT,
  added_at INTEGER NOT NULL,
  PRIMARY KEY (playlist_id, video_id),
  FOREIGN KEY (playlist_id) REFERENCES user_playlists(id) ON DELETE CASCADE
);
  • createPlaylist(id, name) & updatePlaylist(...): Mengelola identitas playlist, deskripsi, dan cover art lokal/URL.
  • addTrackToPlaylist(playlistId, track) & removeTrackFromPlaylist(...): Mengelola lagu di playlist.
  • deletePlaylist(id): Menghapus playlist dengan kaskade penghapusan otomatis lagu-lagunya (ON DELETE CASCADE).

Tabel 6: saved_collections (Koleksi Album & Playlist Tersimpan)

Menyimpan album atau playlist dari YouTube yang disimpan pengguna ke perpustakaan offline.

CREATE TABLE saved_collections (
  id TEXT PRIMARY KEY,
  type TEXT NOT NULL,          -- 'album' atau 'playlist'
  title TEXT NOT NULL,
  browse_id TEXT,
  thumbnail TEXT,
  added_at INTEGER NOT NULL
);
CREATE INDEX idx_saved_collections_type ON saved_collections(type, added_at DESC);
  • saveCollection(MusicItem item): Menyimpan koleksi album/playlist.
  • isCollectionSaved(String id) & removeCollection(String id): Cek dan hapus koleksi tersimpan.
  • getSavedCollections(String type): Mengambil semua koleksi berdasarkan tipenya.

Tabel 7: listening_logs (Wawasan & Statistik Mendengarkan)

Mencatat durasi riil pemutaran lagu setiap kali diputar minimal 15 detik untuk menghasilkan analitik.

CREATE TABLE listening_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  video_id TEXT NOT NULL,
  title TEXT NOT NULL,
  artist TEXT NOT NULL DEFAULT '',
  thumbnail TEXT,
  duration_seconds INTEGER NOT NULL DEFAULT 0,
  listened_seconds INTEGER NOT NULL DEFAULT 0,
  played_at INTEGER NOT NULL
);
CREATE INDEX idx_listening_logs_played_at ON listening_logs(played_at DESC);
CREATE INDEX idx_listening_logs_video ON listening_logs(video_id);
CREATE INDEX idx_listening_logs_artist ON listening_logs(artist);
  • recordListeningLog(...): Mencatat sesi dengar jika durasi dengar riil mencapai ambang batas.
  • getListeningStats({int? sinceTimestamp}): Menghasilkan objek agregasi ListeningStats (total menit, total plays, top tracks, dan top artists) dalam rentang waktu yang dipilih (1 minggu, 1 bulan, 1 tahun, dsb).
💡 Tips Pengujian SQLite (In-Memory Database)

Di unit test (test/database_test.dart), kita menggunakan paket sqflite_common_ffi dengan database in-memory (inMemoryDatabasePath). Database dibuat di memori RAM dan dibersihkan saat test selesai, sehingga tes berjalan sangat cepat (<1 detik) tanpa mengotori filesystem perangkat.

8. Playback Layer: lib/playback/sonora_audio_handler.dart

Jantung pemutar audio native. Menjembatani paket just_audio dengan audio_service agar sistem Android mengenali aplikasi sebagai pemutar musik resmi.

Fitur & Arsitektur Playback:

  1. Antrean Native (ConcatenatingAudioSource): Pemutar menyerahkan perpindahan lagu otomatis (*auto-advance*) ke engine playlist native `just_audio`. Kita tidak perlu membuat timer manual atau memanggil "next" saat lagu selesai.
  2. Serialisasi Permintaan (_enqueue): Jika pengguna menekan lagu A lalu dengan cepat menekan lagu B, fungsi _enqueue memastikan urutan loading dieksekusi teratur tanpa balapan (*race condition*).
  3. Generasi Request (_generation): Setiap kali antrean diganti atau tombol stop ditekan, angka _generation dinaikkan. Jika ada loading lagu lama yang baru selesai beberapa milidetik kemudian, lagu lama akan dibatalkan (*dropped*) karena nomor generasinya sudah basi.
  4. Pemisahan Lifecycle play(): Critical bug fix! Di library just_audio, pemanggilan await player.play() baru akan selesai (complete) saat lagu berhenti/dijeda/selesai. Oleh karena itu, playItems() tidak boleh me-await fungsi play() di dalam antrean loading, melainkan menjalankannya sebagai aksi independen (*fire-and-forget* aman) agar antrean tidak macet selama durasi lagu.
  5. Audio Interruption & Becoming Noisy: Menggunakan audio_session: jika ada panggilan telepon masuk, volume otomatis mengecil (ducking) atau dijeda (pause). Jika kabel headphone dicabut, musik otomatis berhenti seketika.
  6. Native AudioSource & Dekopling ID MediaItem: Stream audio dimuat menggunakan AudioSource.uri(uri, headers: {'User-Agent': ...}) native Android Media3 ExoPlayer (DefaultHttpDataSource). ID kanonik MediaItem disetel langsung ke item.videoId!, mengeliminasi total ketergantungan pemanggilan stream proxy dan mencegah eksepsi fatal SonoraConfigurationException.

16. Tips & Hal Penting untuk Junior Dev

⚠️ 1. Jangan pernah me-await player.play() di antrean serial!

Ingat bahwa AudioPlayer.play() di Flutter baru selesai ketika pemutaran lagu berhenti. Jika Anda menulis await player.play() di dalam fungsi penggantian lagu, antrean berikutnya akan macet total sampai lagu tersebut selesai berputar!

⚠️ 2. Masalah Build Windows (Drive C: vs Drive D:)

Jika proyek berada di drive D: sedangkan folder cache pub berada di C:\Users\..., compiler Kotlin di Windows akan crash saat melakukan perbandingan path relatif untuk incremental cache. Solusinya: selalu sertakan kotlin.incremental=false di android/gradle.properties.

💡 3. Jangan Menaruh String Hex Sembarangan di Widget

Gunakan selalu token warna dari Theme.of(context).colorScheme atau extension context.sonora di lib/ui/theme.dart. Ini memastikan aplikasi Anda secara otomatis mendukung tema Terang (*Light Mode*) dan Gelap (*Dark Mode*) tanpa perlu if-else warna manual.
